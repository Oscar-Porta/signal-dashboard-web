# Signal Dashboard (web)

Front end for the `btc-ml-signal-engine` repository: a landing page with **out-of-sample, net-of-cost** performance metrics, a multi-step sign-up configurator, and public live-history pages for each signal channel.

> **Status: archived.** The site was deployed on Vercel and has been taken offline. Published as a portfolio piece. Informational only — not financial advice.

## Pages

| Route | What it does |
|---|---|
| `/` | Landing page. The equity curve and metrics come from the engine's **walk-forward** validation (net of fees), including the drawdown, not from an in-sample backtest. Includes a return calculator. |
| `/how-it-works` | Plain-language explanation of the rules, the ML filter and the validation method. |
| `/configurator` | Multi-step sign-up flow (coverage → filter level → form). Writes the subscription to Supabase and returns the matching Telegram invite link. |
| `/track/[slug]` | Live history of one channel. Reads the engine's `signals` table and filters at read time by model probability and trading hours, so one table serves every channel. |

## Design decisions worth noting

- **Metrics stay honest.** When an audit of the engine found look-ahead bias, every number on the site was regenerated from the corrected walk-forward results, and the weaker filter level was removed from the sign-up flow instead of being marketed.
- **The web only offers what the engine emits.** Channels without enough out-of-sample evidence were removed from the configurator, so the front end never promises a product the back end doesn't run.
- **Channel-agnostic data model.** The engine stores signals without channel tags; each `/track` page is a filtered view (`ai_proba >= threshold`, hour/weekday window). Adding or retiring a channel doesn't touch the database.

## Stack

Next.js (App Router) · React · TypeScript · Tailwind CSS · Supabase (Postgres + row-level security) · Vercel.

## Running locally

```bash
npm install
cp .env.example .env.local     # Supabase URL + anon key, Telegram invite links
npm run dev
```

The app expects two Supabase tables:

- `subscriptions`: `email`, `telegram_username`, `instrument`, `franja`, `umbral`, `gdpr_consent`
- `signals`: written by the engine (`instrument`, `direction`, `rule`, `entry_price`, `stop_loss`, `tp1`, `risk_pct`, `ai_proba`, `hora_madrid`, `dia_semana`, `status`, `r_multiple`, …)

`data/configurator_metrics.json` is generated by the engine (`src/tools/generate_metrics.py`).

UI copy is in Spanish (the original target audience).
